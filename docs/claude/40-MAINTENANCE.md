# 40-MAINTENANCE：制度檔案維護協議

> 對象：未來要修改 CLAUDE.md 或 docs/claude/* 的任何 session。
> 原則：制度檔案是共用基礎設施，改壞的代價由之後所有 session 承擔。

## 可以自行改（不必問使用者）
- **追加** `LESSONS.md` 教訓條目（照下方格式）。
- 更新 CLAUDE.md「目前狀態」區段（每次實質變更後本來就必須做）。
- 修正**已證實錯誤的事實**：路徑不存在、工具名改了、命令失效。
  修正前必須先驗證（跑一次命令／Glob 確認路徑），並在 commit message
  寫明證據。
- `10-DISPATCH.md` §0 的可用資源清單與 session 實況不符時，照實況更新。
- 錯字、格式修正。

## 動之前必須先問使用者（AskUserQuestion 附改動前後對照；無此工具則以文字提問）
- 刪除或放寬任何規則（例：取消「commit 前必跑測試」、提高重試上限）。
- 改動任務分級（S/M/L）的判準。
- 改動升降級路徑或「驗證不自驗」原則。
- 改動 CLAUDE.md 的「紅線」「分支與部署」節。
- 重排制度檔案結構（合併、拆分、改檔名）——路由表指向會跟著壞。

**判別法**：讓規則「更嚴」或「更準」通常可自行改；讓規則「更鬆」一律先問。

## 改動程序（適用所有制度檔；純錯字/格式修正可免步驟 1 與 4）
1. 備份：`cp <檔案> docs/claude/archive/<檔名>-backup-<YYYY-MM-DD>.md`
   （同日已有備份則跳過）。
2. 修改。
3. 檢查 CLAUDE.md 路由表是否仍指向正確檔案。
4. 派 fresh-context agent read-back（存在、完整、無矛盾、無壞路徑）。
5. commit message 說明改了哪條規則、為什麼、證據是什麼。

## 教訓寫回：LESSONS.md 格式
每次踩坑（返工、驗證失敗、使用者糾正、subagent 兩輪失敗）後追加一條：
```
## 2026-07-06 | 症狀一句話
- 根因：【真正原因，不是表象】
- 規則：【下次遇到 X 就做 Y——要具體到可執行】
- 歸宿：【該併入哪個制度檔的哪一節，或「暫留此處」】
```

## 精簡門檻（防制度膨脹）
- `LESSONS.md` 超過 **20 條或 150 行** → 下次 M/L 級任務開始前先做精簡：
  重複的合併、已併入制度檔的刪除（檔案有 git 歷史，刪了可考古）、
  通用性高的條目移入對應制度檔。
- CLAUDE.md 超過 **120 行** → 把膨脹的內容抽到 docs/claude/ 下的新檔或
  既有檔，CLAUDE.md 只留路由。這條可自行執行（屬「更準」），但不得在
  抽取過程刪規則。
- 「目前狀態」的已完成清單只留**最近 5–8 項**，更舊的直接刪
  （git log 就是完整歷史，不需要搬到別處）。
- 制度檔單檔超過 **250 行** → 檢查是否有可刪的重複與過度舉例；仍超過
  就問使用者是否拆分。

## 版本紀律
- 制度檔改動獨立 commit，不與功能改動混在同一個 commit。
- 永遠不要在 docs/claude/archive/ 裡修改備份檔。
